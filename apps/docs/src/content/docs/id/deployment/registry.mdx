## Mulai dari lokal

Gunakan emulator D1 dan R2 lokal Wrangler:

```sh
bunx karsa db sync
bunx wrangler d1 migrations apply DB --local
bunx karsa db seed
bun run build
```

Pertahankan nama binding `DB` dan `MEDIA` di `wrangler.jsonc`. `.dev.vars` lokal di-gitignore; simpan `BETTER_AUTH_SECRET` dan `KARSA_SETUP_TOKEN` hasil scaffold di sana. Gunakan Wrangler secret untuk environment deploy:

```sh
bunx wrangler secret put BETTER_AUTH_SECRET
bunx wrangler secret put KARSA_SETUP_TOKEN
```

Jika modul booking dipasang, konfigurasikan widget Turnstile terpisah untuk aplikasi ini. Atur `TURNSTILE_SITE_KEY` dan `TURNSTILE_HOSTNAMES` production yang dipisahkan koma sebagai variable deployment, lalu simpan `TURNSTILE_SECRET` dengan Wrangler. Jangan memakai dummy key scaffold di production, jangan memasukkan `localhost` ke hostname production, dan jangan pernah mencetak secret ke log atau laporan.

## URL kanonis dokumentasi

Atur `DOCS_SITE_URL` ke origin dokumentasi publik saat menjalankan build deployment. Build lokal sengaja memakai default `http://localhost:4321`, sedangkan nilai deployment mengendalikan URL kanonis dan sitemap tanpa meng-hardcode domain produksi yang belum dikonfirmasi.

```sh
DOCS_SITE_URL=https://docs.example.com bun run --cwd apps/docs build
```

## Akses registry

Paket publik diambil dari npm. Jika modul terpilih berada di registry privat, atur scope `@karsa` dan credential di `.npmrc` user atau CI; jangan commit token. Verifikasi graph paket sebelum menjalankan CLI agar `karsa add` dapat menyelesaikan modul dan dependency-nya.

## Checklist deploy

1. Buat database D1 dan bucket R2 nyata, lalu perbarui binding deployment.
2. Terapkan plan migrasi append-only ke database remote, termasuk migration upload/idempotency orders, fingerprint/quota booking, dan inventory-allocation catalog.
3. Tambahkan secret dan periksa konfigurasi origin/allowed-host. Selesaikan setup pertama memakai bootstrap token.
4. Jika ada media SVG lama, konversi dan upload ulang sebagai raster yang diizinkan; route media publik sekarang mengembalikan `415` untuk metadata MIME tidak aman.
5. Build dengan registry dan lockfile yang sama dengan CI.
6. Smoke-test route publik, mode auth, route terjaga, download media, Turnstile booking, idempotency checkout, dan satu alur milik modul.

Jangan melakukan seed remote dengan jalur `karsa db seed` yang hanya lokal. Gunakan migrasi yang direview atau import operasional eksplisit untuk data production, lalu simpan output command sebagai bukti.
